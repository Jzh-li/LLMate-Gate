## 0. 通用约定

### 0.1 语言与格式

- **Go** 用于网关、检测器客户端、仿真引擎、缓存
- **TypeScript** 用于 VS Code 扩展、桌面前端
- **JSON** 用于配置文件、审计日志、进程间通信
- 所有 `uint8` 偏移采用 **UTF-8 字节偏移**，`[start, end)` 半开区间

### 0.2 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 包名 | 小写单数 | `detector`、`replacer` |
| 导出类型 | PascalCase | `MappingTable`、`DetectRequest` |
| 导出函数 | PascalCase，动词开头 | `Detect`、`Replace` |
| JSON 字段 | snake_case | `conversation_id`、`start_offset` |
| 错误变量 | `Err` 前缀 | `ErrDetectorUnavailable` |

### 0.3 错误模型（统一）

```go
// gateway/internal/errors/errors.go
package errors

type Code string

const (
    CodeInvalidRequest      Code = "invalid_request"
    CodeInvalidConfig       Code = "invalid_config"
    CodeDetectorUnavailable Code = "detector_unavailable"
    CodeDetectorTimeout     Code = "detector_timeout"
    CodeCircuitOpen         Code = "circuit_open"
    CodeReplaceFailed       Code = "replace_failed"
    CodeRestoreFailed       Code = "restore_failed"
    CodeUnauthorized        Code = "unauthorized"
    CodeUpstreamError       Code = "upstream_error"
    CodeVaultSealFailed     Code = "vault_seal_failed"
    CodeNotFound            Code = "not_found"
)

type Error struct {
    Code    Code   `json:"code"`
    Message string `json:"message"`
    // 链式原因（不对外暴露，仅日志）
    cause error
}

func (e *Error) Error() string { return string(e.Code) + ": " + e.Message }
```

**HTTP 响应错误体**（返回给调用方）：

```json
{ "error": { "code": "detector_timeout", "message": "PII detection exceeded 500ms" } }
```

**错误码 → HTTP 状态映射**（11 个码全覆盖，**以本表为准**）：

| 错误码 | HTTP | 产生场景 |
|---|---|---|
| `invalid_request` | 400 | 请求体 / 参数非法 |
| `invalid_config` | 400 | 配置非法。**仅在启动期产生**，不经 HTTP 返回；给 400 是因为它与 `invalid_request` 同族（都是调用方输入问题），不是运行时响应 |
| `unauthorized` | 401 | 凭据缺失或错误（数据面 / 控制面分凭据，见 §7.3） |
| `not_found` | 404 | 映射表不存在 / 已过期 / 不属于本调用面。**三种情况刻意不可区分**，避免变成 ID 存在性探针（见 §7.3） |
| `detector_timeout` | 502 | 检测超出 deadline |
| `circuit_open` | 502 | 检测器熔断器打开 |
| `upstream_error` | 502 | 上游错误 |
| `detector_unavailable` | 500 | 检测器侧车不可用 |
| `replace_failed` | 500 | 替换阶段失败 |
| `restore_failed` | 500 | 还原阶段失败 |
| `vault_seal_failed` | 500 | 密文写入失败 |

> ⚠️ **本节的三个已知偏差（2026-09-23 实测登记，`Specs/06` #34）**
>
> 1. **契约指名的映射函数当前无人调用。** 本节的 `errors.HTTPStatus` / `errors.Response` /
>    `errors.Body` / `errors.ErrorPayload` 四个导出符号**全仓零调用**；数据面实际生效的是
>    `gateway/internal/proxy` 里的 `statusForCode` + `writeError`（未导出，**本节的重复实现**）。
>    两份映射对 `invalid_config` 结论不同（前者 400、后者落 default 500）。
>    由于 `invalid_config` 只在启动期产生、不进 HTTP，这是**潜在分歧而非在线缺陷**。
>    **对照上表写代码时，以本表为准**；改动任一份实现都必须同步另一份或先消除重复。
> 2. **panic 路径的响应体与状态码不同源。** `server.wrap` 的 recover 分支发 HTTP **500**，
>    但 body 里写的是 `code: "upstream_error"`（按本表 = 502）。客户端若按 `code` 判错误类
>    会得到与状态码不一致的结论。
> 3. **调试面板的错误码不在本契约承诺内。** `gateway/debug` 使用
>    `marshal_failed` / `detector_failed` / `rule_apply_failed` / `invalid_dictionary` /
>    `registry_save_failed` / `invalid_registry` 六个**面板私有**码（另有
>    `invalid_request` / `replace_failed` 两个复用本表）。面板是 **loopback-only 的本地
>    调试面**（默认仅绑 `127.0.0.1`，`--no-debug` 后整组路径不注册，见 §10.1 绑定约束），
>    故明确豁免本契约的稳定性要求：
>    这六个码可随时变更，调用方不得依赖。
> 4. **`405 Method Not Allowed` 是全节唯一的「无错误码 + 非 JSON」响应 —— 显式声明的例外。**
>    它由 `http.Error` 产出（`text/plain`，body 恰为 `method not allowed`），**不经**任何
>    `errors.Code` 通道，因此不在上表 11 个码之内、也不遵循本节的错误响应体约定。
>    当前只有 `/v1/privacy/{redact,restore}` 与调试面板会返回它（详见 §4 的门禁说明）。
>    **这是刻意保留的例外**，不是遗漏：405 表达的是「**这个方法本身不被接受**」，
>    与「你的请求内容有问题」（`invalid_request`）不是一类，硬塞进错误码表会让
>    客户端误以为换 request body 就能重试成功。
>    **调用方必须同时处理两种错误形状**：读 `Content-Type` —— `application/json` 按
>    上表解析 `error.code`；否则按纯文本处理，只看 HTTP 状态码。

**禁止自造错误码**（见附录 A）：数据面与控制面的**任何对外错误**都必须取自上表。
本节的两处**显式豁免**完整清单：`gateway/debug` 的 6 个面板私有码（见第 3 条）、
`405` 的无码纯文本体（见第 4 条）。两处均已写明范围与理由，**不得扩散到其他路径**。

### 0.4 上下文与超时

- 所有跨模块调用第一个参数为 `ctx context.Context`
- 默认超时：**检测 500ms**、**上游转发 30s**、**Vault 加解密 100ms**
- 超时一律返回 `context.DeadlineExceeded`，由调用方转换为 `CodeDetectorTimeout`

### 1.2 模块依赖方向（禁止反向）

```
server → proxy → { detector, replacer, simulator, vault, cache, audit }
detector → (PII Engineer sidecar，进程外)
replacer → vault
simulator → vault
vault → config
cache → vault
```

**规则**：`detector` 不得依赖 `replacer`；`replacer` 不得依赖 `server`。循环依赖即设计错误。

**上图的补充与一处更正（2026-09-23 实测，`Specs/06` #37）**：

```text
registry → {internal/detector, pkg/types}   debug → registry     cmd/llmate-gate → registry
detector → {pkg/cn, pkg/global, pkg/types}  simulator → {pkg/cn, pkg/types}
pkg/global → pkg/cn
```

`pkg/cn` 与 `pkg/global` 是**被多处依赖的底层校验库**，自身不依赖任何内部包：
`pkg/cn` ← `detector` / `simulator` / `pkg/global`；`pkg/global` ← `detector`。
`pkg/types` 是被依赖最广的叶子（上表未逐一列出）。

⚠️ **注意 `registry` 不在 `pipeline` 之下**：它是 `detector` 的**装饰器**
（`main.go:112` 的 `registry.Wrap(det, piiReg)`），在 `pipeline` 之外完成包装。
⇒ 它**没有引入独立的数据通路**：登记表命中产出的实体与内层检测结果**合并进同一条**
替换/还原链路（这也是「补召回前置层」而不是「第二套检测器」的原因）。

⚠️ **更正**：`README` 曾写 `pkg/global` 与 `pkg/cn`「**解耦、不互相依赖**」，这与代码不符 ——
`pkg/global` **确实引用** `pkg/cn`（`global.go:102` 的 `cn.LuhnValid`），且代码注释明确写着
「复用：信用卡 Luhn 复用 `pkg/cn.LuhnValid`（中国 Luhn = 国际 Luhn，算法一致）」。
**准确表述是：单向依赖 `global → cn`，无环；不存在互相依赖，但两者并非解耦。**
改动任一个的 Luhn 实现都会影响另一个 —— 这正是「解耦」一词会掩盖的风险。

## 2. 检测引擎接口（detector）

### 2.1 Sidecar 契约（PII Engineer HTTP）

PII Engineer 作为 sidecar 运行，`detector` 包通过 HTTP 调用。

**请求**：

```http
POST http://127.0.0.1:8000/api/detect
Content-Type: application/json
```

```json
{
  "text": "张三的手机号是13800138000",
  "conversation_id": "conv_8821",
  "entities": ["zh_person_name", "zh_phone", "zh_id_card"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | ✅ | 待检测文本（UTF-8） |
| `conversation_id` | string | ❌ | 会话 ID，命中缓存时传入 |
| `entities` | []string | ❌ | 限定实体类型，空=全部启用 |

**响应**：

```json
{
  "entities": [
    { "type": "zh_person_name", "value": "张三", "start": 0, "end": 6, "score": 0.97 },
    { "type": "zh_phone", "value": "13800138000", "start": 18, "end": 29, "score": 0.99 }
  ],
  "redacted": "<<zh_person_name_1>>的手机号是<<zh_phone_1>>",
  "latency_ms": 180
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `entities` | []Entity | 按 `start` 升序排列 |
| `redacted` | string | sidecar 生成的占位符文本（**仅供参考**，代理以自身替换结果为准） |
| `latency_ms` | int64 | 本次检测耗时 |

**批量接口**：`POST /api/detect/batch`，body `{ "items": [{"text":...}, ...] }`，返回 `[DetectResponse]`。用于 tool_call 多参数场景，减少往返。

**健康检查**：`GET /healthz` → `200 { "status": "ok" }`。

### 2.2 Go 客户端接口

```go
// internal/detector/client.go
package detector

import (
    "context"
    "gateway/pkg/types"
)

// Client 是检测引擎的客户端抽象（便于测试 mock）
type Client interface {
    // Detect 对单段文本做 PII 检测
    // 超时 500ms，失败返回 errors.ErrDetectorTimeout / ErrDetectorUnavailable
    Detect(ctx context.Context, req *types.DetectRequest) (*types.DetectResponse, error)

    // DetectBatch 批量检测，顺序与输入一致
    DetectBatch(ctx context.Context, reqs []*types.DetectRequest) ([]*types.DetectResponse, error)

    // Health 健康检查
    Health(ctx context.Context) error
}

// Sidecar 管理（server 启动时调用）
type Sidecar interface {
    Start() error   // exec.Command 拉起 PII Engineer
    Stop() error
    WaitHealthy(timeout time.Duration) error // 轮询 /healthz，最多重启 3 次
}
```

### 2.3 共享类型（pkg/types）

```go
// pkg/types/detect.go
package types

type DetectRequest struct {
    Text           string   `json:"text"`
    ConversationID string   `json:"conversation_id,omitempty"`
    Entities       []string `json:"entities,omitempty"`
}

type DetectResponse struct {
    Entities  []Entity `json:"entities"`
    LatencyMs int64    `json:"latency_ms"`
}

type Entity struct {
    Type   string  `json:"type"`    // 实体类型，见 §6.1
    Value  string  `json:"value"`   // 原文
    Start  int     `json:"start"`   // UTF-8 字节偏移，含
    End    int     `json:"end"`     // UTF-8 字节偏移，不含
    Score  float64 `json:"score"`   // [0, 1]
}

type Fate int

const (
    FateReversible Fate = iota // 占位符/仿真，可还原
    FateMask                    // 部分遮盖，如 138****8000
    FateRedact                 // 不可逆移除
)
```

### 4.1 请求处理流程（每个端点共用）

```
1. 鉴权：校验 Authorization / X-Api-Key（面与令牌来源见 §4.2）
2. 解析：提取 messages / tool_calls / multimodal content
3. 替换：对每段文本调用 replacer.Replace（内含 detector + vault）
4. 转发：构造上游请求，保留原始 headers（去除鉴权）
5. 响应：
   - 非流式：整包还原后返回
   - 流式 SSE：逐块还原（§5.3）
6. 审计：记录 AuditEvent（§9）
```

### 4.2 认证

**令牌来源**（`config.ResolveAuthToken`，优先级从高到低）：

1. `gateway.auth_token` 非空 → 使用它
2. 否则 `gateway.allow_unauthenticated: true` → **不鉴权**（显式选择，启动日志打 WARNING）
3. 否则读 `gateway.auth_token_file`（默认 `./auth_token`）：文件不存在则生成 32 字节随机令牌、以 `0600` 落盘、启动日志打印一次

⇒ **「没配 `auth_token`」不再等于「不鉴权」。** 空令牌只可能来自显式的 `allow_unauthenticated`，不会因为忘写而静默裸奔。令牌跨重启稳定，客户端只需配置一次。

**分面**：

| 面 | 路径 | 令牌 |
|---|---|---|
| 探针 | `/healthz` | **不鉴权**——探针通常不持凭据，把「服务没起来」与「没带令牌」混成同一个 401 会让启动排查变难 |
| 数据面 | `/v1/chat/completions` 等、`/metrics` | `auth_token`（配置或自动生成） |
| 控制面 | `/v1/privacy/redact`、`/v1/privacy/restore` | `gateway.control_auth_token`；留空则回退数据面令牌 |
| 控制面（面板静态壳例外） | `/_debug`、`/_debug/*` | **不鉴权** + 仅回环（不含请求数据，且是输入令牌的载体） |
| 控制面（面板数据） | `/_api/*`、`/ws/events` | 同控制面令牌，或面板 Cookie（见 §10.1） |

控制面能按 `request_id` 还原原文，数据面只转发——两者权限不在一个级别，因此允许分凭据。两个令牌互不通用。

**鉴权先于路由（实测 2026-09-23）**：未持凭据时，**未知路径同样返回 `401` 而不是 `404`** ——
`root.Handle("/", authMiddleware(...))` 把整棵 `/` 包住，鉴权层在路由之前生效。
因此**状态码差异不能当作「端点是否存在」的探针**：

| 请求 | 无令牌 | 带令牌 |
|---|---|---|
| `DELETE /v1/totally-bogus`（不存在） | `401` | `404` |
| `DELETE /v1/privacy/restore`（存在 + 方法错） | `401` | `405` |

**还原的来源约束（2026-09-16）**：`/v1/privacy/restore` 只能还原由 `/v1/privacy/redact`
建立的映射表。数据面的映射表（由 `/v1/*` LLM 请求建立，其 `request_id` 取自客户端可指定的
`X-Request-ID`）**不可经该 API 还原**，否则「知道一个 request_id」就等于「能读出那次请求的
原文」。映射表带 `origin` 字段区分两者，未标注的按数据面处理。不可还原统一返回
`404 not_found`，与「不存在 / 已过期」不可区分——避免变成 ID 存在性探针。

**请求凭据形式**：`Authorization: Bearer <token>` 或 `X-Api-Key: <token>`，均以常量时间比较；不匹配返回 `401 unauthorized`。

- 转发上游时使用配置中的 `upstream_api_key`，**不从客户端凭证透传**

## 5. 占位符替换（replacer）

### 5.1 接口

```go
// internal/replacer/replacer.go
package replacer

import (
    "context"
    "gateway/pkg/types"
)

type Replacer interface {
    // Replace 对文本做脱敏，返回脱敏后文本 + 映射条目
    // 同一 (request_id, entity_type, value) 必须映射到同一占位符（双射）
    Replace(ctx context.Context, req *ReplaceRequest) (*ReplaceResult, error)

    // Restore 在响应文本中还原占位符为原值
    Restore(ctx context.Context, req *RestoreRequest) (string, error)
}

type ReplaceRequest struct {
    Text           string
    RequestID      string
    ConversationID string
    Entities       []types.Entity  // 来自 detector
    Fate           types.Fate     // 默认 Reversible，不可逆类型见 §6.1
}

type ReplaceResult struct {
    Text   string
    Entries []types.MappingEntry
}

type RestoreRequest struct {
    Text      string
    RequestID string
    // 若为空，从 vault 按 RequestID 加载映射表
    Entries   []types.MappingEntry
}
```

### 5.2 占位符协议

**格式**：`<<{entity_type}_{index}>>`，例 `<<zh_person_name_1>>`。

**规则**：

1. **同值同占位符**：同一请求内 `"张三"` 始终 → `<<zh_person_name_1>>`（保证 LLM 跨句指代）
2. **不同类型即使值相同 → 不同占位符**：身份证 `110101...` 与人名 `110101` 不冲突
3. **index 按 type 独立计数**：`zh_person_name_1, _2`；`email_1, _2`
4. **偏移保留**：MappingEntry 记录占位符在**脱敏文本**中的 `[start, end)`，还原时按偏移精准替换，**禁止** `strings.ReplaceAll`（避免正文恰含 `<<...>>` 被误还原）

### 5.3 流式还原（trie 缓冲）

```go
// internal/replacer/stream.go
type StreamRestorer struct { /* trie *PlaceholderTrie; buf []byte */ }

// Write 接收上游 SSE 分块，返回已可输出的完整还原块
// 不完整的占位符前缀（如收到 "<<zh_person_na"）留缓冲，跨块拼接
func (s *StreamRestorer) Write(chunk []byte) ([]byte, error)
func (s *StreamRestorer) Close() ([]byte, error) // 刷新剩余
```

**规则**：

- trie 以占位符前缀 `<<` 触发，消费直到 `>>` 闭合
- 闭合后查映射表还原；查不到 → **保留原占位符**（fail-safe，不报错）
- `Close()` 时若缓冲仍不完整 → 记录 metric `stream_orphan_placeholder`

### 6.1 实体类型与规则（权威表）

|---|---|---|

### 6.2 身份证校验位（必须精确实现）

```
算法：ISO 7064 / GB 11643 加权校验
输入：17 位数字 body
权重：W = [7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]
校验码表：R = "10X98765432"（index = sum % 11）
```

```go
// internal/simulator/idcard.go
package simulator

func idCardChecksum(body17 string) byte {
    if len(body17) != 17 { panic("body must be 17 digits") }
    weights := []int{7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2}
    checkMap := "10X98765432"
    sum := 0
    for i, c := range body17 {
        if c < '0' || c > '9' { panic("non-digit") }
        sum += int(c-'0') * weights[i]
    }
    return checkMap[sum%11]
}

// Generate：前 17 位随机（行政区划用公开省级代码），第 18 位 = checksum
func (g *Generator) GenerateIDCard() string { /* ... */ }
```

**约束**：

- 行政区划码仅用**公开的省级代码**（如 11=北京、31=上海），避免对应真实自然人
- 生成的号码**绝不对应真实身份**，禁止用于真实身份核验
- 相同输入 → 相同输出（HMAC 派生种子 = session_key + entity_type + value）

## 7. Vault（映射表存储）

### 7.1 数据结构

```go
// pkg/types/vault.go
package types

type MappingTable struct {
    RequestID      string         `json:"request_id"`
    ConversationID string         `json:"conversation_id,omitempty"`
    Entries        []MappingEntry `json:"entries"`
    CreatedAt      time.Time      `json:"created_at"`
    ExpiresAt      time.Time      `json:"expires_at"`
    // Origin 建立该表的调用面："data"（/v1/* LLM 请求）| "control"（/v1/privacy/redact）。
    // 只有 "control" 可经 /v1/privacy/restore 还原；空值按 "data" 处理（缺省取收紧的一侧）。
    Origin         string         `json:"origin,omitempty"`
}

type MappingEntry struct {
    Placeholder string `json:"placeholder"`       // "<<zh_person_name_1>>"
    Original    []byte `json:"-"`                  // 明文，不序列化
    EntityType  string `json:"entity_type"`
    Score       float32 `json:"score"`
    Fate        Fate   `json:"fate"`
    Start       int    `json:"start_offset"`      // 脱敏文本中的偏移
    End         int    `json:"end_offset"`
    FakeValue   []byte `json:"fake_value,omitempty"` // v1.1 仿真值
}
```

### 7.2 接口

```go
// internal/vault/vault.go
package vault

import (
    "gateway/pkg/types"
)

type Vault interface {
    // Put 存储映射表，设置 TTL（默认 30m）
    Put(table *types.MappingTable) error

    // Get 按 RequestID 加载（还原时调用）
    Get(requestID string) (*types.MappingTable, error)

    // Seal 序列化 + AES-256-GCM 加密后落盘（若启用了持久化）
    Seal(table *types.MappingTable) ([]byte, error)

    // Unseal 解密 + 反序列化
    Unseal(data []byte) (*types.MappingTable, error)

    // Sweep 清理过期条目（后台定期执行）
    Sweep() (int, error)
}
```

### 7.3 加密

- **算法**：AES-256-GCM（认证加密，防篡改）
- **密钥派生**：`scrypt(salt=session_id, N=32768)`，密钥存内存，**不落盘**
- **序列化**：MessagePack（紧凑）或 JSON（可读）；落盘文件格式：`[4字节 magic "LMGV"][12字节 nonce][ciphertext+tag]`
- **TTL**：默认 30m，过期后 `Get` 返回 `errors.ErrNotFound`（还原失败 → 占位符保留，fail-safe）

### 7.4 内存安全

- `Original` 字段使用 `[]byte`，处理完毕显式 `memzero`（清空）
- 映射表不再需要时主动 `delete`，避免长期驻留

## 8. 检测缓存（cache）

> ⚠️ **2026-09-10 实现说明**：实际实现不是"内存 LRU + 内容哈希"，而是
> `internal/cache/merkle.go` 的 **per-conversation 有序段数组 + SHA-256 前缀链**增量检测
> （只检新增尾部段；历史被改写时在首个分叉处截断重检）。缓存键仍绑定 `conversation_id`，**契约义务未被破坏**。
> 本规范 §8.1 的接口描述**未回写**（保留原文），待你确认后同步（`SPEC_ALIGNMENT.md` C18）。

### 8.1 接口

```go
// internal/cache/cache.go
package cache

import "gateway/pkg/types"

type Cache interface {
    // Get 命中则返回缓存的检测结果（含实体列表）
    Get(conversationID string, textHash [32]byte) (*types.DetectResponse, bool)

    // Put 按 (conversation_id, text_hash) 存储
    Put(conversationID string, textHash [32]byte, resp *types.DetectResponse) error

    // Invalidate 会话结束/超时时调用
    Invalidate(conversationID string) error
}
```

### 8.2 规则

- **键绑定 `conversation_id`**：跨请求/跨用户命中会导致实体错乱，严禁仅用 text 哈希
- **文本哈希**：`SHA-256(text)`；增量场景下存 Merkle 树（v1.1）
- **实现**：v1 用进程内 `sync.Map` + LRU（max 10000 条）；分布式部署用 Redis（可选）
- **TTL**：与 `config.detection.cache.ttl` 一致（默认 30m）

### 10.1 端点清单

**认证口径（2026-09-16 收紧）**：面板数据端点能看到请求明文与登记表（用户自报的真实 PII

**面板 Cookie**：浏览器在 `fetch` / WebSocket 上无法携带 `Authorization` 头，因此提供
引导通道 —— `GET /_debug?token=<控制面令牌>` 校验通过后下发 `HttpOnly; SameSite=Strict`
Cookie 并 302 回不带查询串的同一路径，之后页面内请求自动携带。Cookie 值即控制面令牌
本身（同一份凭据的另一个载体），且**只对面板路径生效**，不适用于 `/v1/privacy/*`。

**两层防线**：所有面板路由仍保留「仅回环」（按 `RemoteAddr` 判定，不读 `X-Forwarded-For`）。
回环检查挡不住「同机反向代理把 `RemoteAddr` 变成 127.0.0.1」，令牌挡不住「网关绑了
0.0.0.0 且无同机代理」——两者互补。

> ⚠️ **2026-09-10 补录**：`GET /_api/audit?limit=N` 已在 `gateway/debug/handler.go` 实现，
> 是审计 Tab（`UI设计.md` §2.4）的数据源，但本规范 §10.1 原表**未登记**。
> 按 §11"规范先行"的要求，本次属**实现先于规范**；现补录以消除不一致（`SPEC_ALIGNMENT.md` C17）。

**绑定约束**：默认仅 `127.0.0.1`；`--no-debug` 关闭后所有 `/_debug`、`/ws/events`、`/_api/*` 返回 404
（注意 404 而非 401：未声明挂载时这些路径根本不注册，鉴权层不会留下痕迹）。

## 12. 判断引擎契约（Judge）

> 引入版本：v1.2（2026-09-23）。对应 `pkg/types/judge.go` 与 `internal/judge/`。
> 状态：**骨架已实现（S1–S5），默认不启用（`judgment.enabled=false`）**。

### 12.1 定位：看动作，不看内容

§2 的检测引擎回答「这段文本里有没有 PII」；本层回答「**这个动作要不要拦**」。
两者观测对象不同、判据不同、时序不同，因此是并列的两条链路，不是一条链路的上下层。

判断层**不替代**检测层：命中 §2 的实体照旧走 §5 的替换；判断层只在旁路给风险结论。

**四条不可妥协的红线：**

| # | 红线 | 技术落点 |
|---|---|---|
| R1 | **模型不出决策，只出证据** | `Evidence` 类型里**没有 action 字段**；`Action` 只能由 `Mapper` 产出（§12.5） |
| R2 | **判断层不联网** | `base_url` 只允许回环/私网/链路本地；配置期拒绝（§12.7） |
| R3 | **不改现有语义** | 判断层只读 `ActionDescriptor`，不写 vault、不改占位符、不动响应字节 |
| R4 | **fail-safe，不 fail-open** | 超时 / 解析失败 / 能力塌缩 / 全链不可用 → 降级或 `review`，绝不静默 `allow` |

R1 是编译期成立的隔离，不是纪律要求——后端拿不到产出 `Action` 的类型。

### 12.2 共享类型（`pkg/types/judge.go`）

```go
// ActionDescriptor 一次待判断的行为。
type ActionDescriptor struct {
    Kind           ActionKind       // tool_call | egress_text | mcp_ask
    Phase          ObservationPhase // proposal（执行前）| executed（执行后）
    Tool           string           // Bash / shell / read_file ...
    Target         string           // host / 路径 / 命令首词
    Argv           []string         // 归一化后的参数序列（采集侧做一次，各后端复用）
    Size           int              // 字节数 / 文件数
    Seq            int              // 会话内序号（序列判定用）
    ConversationID string
    RequestID      string
    Meta           map[string]string // batch_count / entropy / history_hits ...
}

// Evidence 后端给出的证据——注意：没有 action。
type Evidence struct {
    Category   ActionCategory // 闭集，见 12.4
    Severity   float64        // 0..1
    Confidence float64        // 0..1
    Reasons    []string       // 人类可读判据（进审计）
    Engine     string         // 产出该证据的后端名 = backends[].name
    LatencyMs  int64
}

// Verdict 最终裁决（确定性代码算出来的）。
type Verdict struct {
    Action Action // allow | redact | review | block
    Evidence      // 内嵌：证据随裁决一起走
    Degraded bool // 该裁决是否来自降级（首个后端未给结论，由后备后端给出）
}
```

**闭集一：`ActionCategory`（行为类别）**

| 值 | 含义 |
|---|---|
| `unknown` | **一等公民**：后端自认判不了。Mapper 对它 → `review`（不是放行） |
| `benign` | 明确无害 |
| `pii` | 内容级 PII（与 §2 重叠，用于整段判定的场合） |
| `credential` | 凭证 / 密钥类（`.ssh` / `.aws` / `.env` / `id_rsa`） |
| `bulk_read` | 批量读取（含读 `.git`、递归遍历仓库） |
| `archive` | **打包归档**（`tar` / `zip` / `git archive` / `7z`） |
| `exfil` | 外传意图 |
| `network_egress` | 非白名单出站 |
| `destructive` | 删改类破坏动作 |

> `archive` 相对方案初稿的闭集新增：本次需求的原始场景是「打包整个代码仓库」，
> 它在 `bulk_read` / `exfil` 里表达不准确——「读了整仓」与「把整仓压成一个文件
> 准备外发」是两个动作，后者才是外发的前一步，且规则侧可精确识别。

**闭集二：`Action`（裁决动作）**：`allow` | `redact` | `review` | `block`
**闭集三：`SchemaMode`（约束解码）**：`json_schema` > `gbnf` > `format` > `prompt_only`
**闭集四：`ActionKind`**：`tool_call` | `egress_text` | `mcp_ask`

### 12.3 后端接口（`internal/judge`）

```go
// Judge 一个判断后端。与 detector.Client 同范式：单一职责、可替换、能力自声明。
type Judge interface {
    Name() string
    Capabilities() types.Capabilities
    Judge(ctx context.Context, d types.ActionDescriptor) (types.Evidence, error)
    Health(ctx context.Context) error
}

// Capabilities 五项能力声明，每一项各自对应一条降级路径。
type Capabilities struct {
    Categories      []ActionCategory // 空 = 支持全部
    SchemaModes     []SchemaMode     // 空 = 仅 prompt_only（最保守假设）
    GivesConfidence bool             // false 时 Mapper 不做 confidence 加权
    MaxInputBytes   int              // 0 = 不限
    Deterministic   bool             // false 时不参与「同输入必同动作」的宣称
}
```

**实现方三条义务：**

1. 判不了时返回 `Category == unknown`，**不是** `benign`——弱模型被迫给假 benign 就是「自信地错」；
2. 自身异常返回 `error`，由 `Chain` 降级；
3. 除访问自己的 `base_url` 外无任何网络/文件副作用。

错误语义：`ErrUnavailable`（不可用）、`ErrInvalidOutput`（输出越闭集）、`ErrInputTooLarge`（超长）。

### 12.4 后端矩阵（`kind`）

| `kind` | 协议 | 覆盖的 runtime | 说明 |
|---|---|---|---|
| `rules` | 进程内 | — | **默认、零依赖、fail-closed 安全网** |
| `openai` | `POST {base_url}/chat/completions` | Ollama / llama.cpp server / vLLM / LM Studio / LocalAI | **收敛点：一个适配器吃下绝大多数本地模型** |
| `http` | 自定义 JSON | 任意自建服务 | 逃生口 |

> **`laya` / `localjev` 不是独立 kind。** 它们要么暴露 OpenAI 兼容接口（用 `openai`），
> 要么给自定义 JSON（用 `http`）。新增一个模型不该新增一行 Go 代码——这是「一个适配器
> 吃下绝大多数」能否成立的分水岭。

**`chain` 不是 kind 而是装配方式**：`judgment.backends` 列表本身就是一条链（§12.6）。

### 12.5 确定性 Mapper（`internal/judge/map.go`）

```
Map(Evidence) → Verdict：
  1. Category == unknown                    → review
  2. GivesConfidence 且 confidence < 0.50    → review   （结论不可信，不落任何档）
  3. score = Severity（GivesConfidence 时再乘 Confidence），落阈值表：
       score ≥ block  → block
       score ≥ review → review
       score ≥ redact → redact
       else           → allow
```

第 2 步覆盖两个方向的失效：「不可信的高危结论」不能触发不可逆动作，
「不可信的低危结论」不能被当成「没事」。两者都交人，代价只是多几条 `review`。

**`benign` 不做特例。** 它只影响统计与自检探针，不影响档位。否则
「`benign` + 高 severity」这种自相矛盾的输出会被静默放行——取更严的一侧才安全。

**阈值表 per-backend（强制）**：`confidence` 跨后端不可比，全局一套阈值等于假定
各后端 severity 分布相同，该假定不成立。每个后端可用自己的 `thresholds` 覆盖。

`Mapper` 是纯函数 + 不可变配置：同输入必同输出。这是「同输入必同 action」
可进 CI 回归的技术基础。

### 12.6 降级链语义（`internal/judge/chain.go`）

顺序 = `judgment.backends` 的顺序，应按**语义能力降序**排列（模型在前、`rules` 在最后）。

| 语义 | 定义 |
|---|---|
| 命中 | 首个返回 **非 `unknown`** 结论的后端 |
| `unknown` | 视为「没答」，**继续往下问**（若算命中，一个恒返回 unknown 的坏模型会堵死整条链） |
| 降级 | 命中者的下标 > 0 时，`Verdict.Degraded = true` |
| 全部 `unknown` | 返回最后一个给出结论的证据 → Mapper 转 `review` |
| 全部 `error` | `Chain` 返回 error → 调用方用 `Evaluator.FallbackVerdict`（按 `fail_closed` 映射） |
| `Health` | 至少一个后端可用即整链可用（「`rules` 永不缺席」在健康检查上的体现） |

### 12.7 配置（`judgment` 段）

键名与校验规则见 `internal/config/judgment.go`，示例见 `configs/config.example.yaml`。

| 键 | 默认 | 校验 |
|---|---|---|
| `enabled` | `false` | `true` 时 `backends` 不得为空（空转配置即错误） |
| `mode` | `shadow` | 闭集 `shadow`/`enforce` |
| `fail_closed` | `true` | 后端全不可用时 → `review`；`false` → `allow`（仍留审计） |
| `timeout` | `300ms` | `(0, 1s]`。超过 1s 的判定不该挂热路径，该改用 shadow |
| `backends[].name` | — | 非空且唯一 |
| `backends[].kind` | — | 闭集 `rules`/`openai`/`http` |
| `backends[].base_url` | — | `openai`/`http` 必填，且**必须回环/私网**；`rules` 不得有 |
| `backends[].model` | — | `openai` 必填；`rules` 不得有 |
| `backends[].schema_mode` | `prompt_only` | 闭集；只支持 `prompt_only` 时解析失败 ⇒ `review` |
| `backends[].timeout` | 继承全局 | `(0, 1s]` |
| `backends[].thresholds` | 继承全局 | 严格递减 |
| `thresholds` | `{0.85, 0.55, 0.30}` | 严格递减，∈[0,1] |
| `points.*` | 全 `false` | 四个判断点分开关（灰度上线） |
| `whitelist.hosts/tools` | `[]` | 命中即 `allow`，不进后端 |

**`base_url` 只允许本机/内网**，被拒的两类：公网 IP（违反「数据不出机」）；
非 IP 的主机名（配置期无法验证它解析到哪里，而 DNS 可被改）。写 IP 是替代路径。

### 12.8 观测位与诚实边界

判断的可靠性取决于**看得见**，而不取决于模型强弱。三个位置的时序完全不同：

| # | 观测位 | 看得见什么 | 时序 | 现有实现 |
|---|---|---|---|---|
| ① | 当轮响应流 | 模型**提议**的 `tool_calls` | **执行前** | 未接（需流式中断） |
| ② | 下一轮请求体 | 回灌的 `tool_use`/`tool_result`、`arguments` | 执行后 | 旁挂点（P2） |
| ③ | 内部思考流 | `thinking` / `reasoning` | 不保证回传 | **不接且不该接** |

③ 在实现里是**不透明块**（`privacy.go` 的 `opaqueBlockTypes`，含 `thinking` /
`redacted_thinking` / `reasoning` / `signature`），整子树跳过。两个理由：
重写会被上游拒（Anthropic 的 thinking 带签名）；更根本的是这些字段**下一轮常常不回传**。

⇒ **判定必须建在 `tool_calls` / `tool_use` 这个协议强制的结构化字段上**，不建在思考流上。

**诚实宣称**（不得越界）：

> 进入模型上下文的行为（工具调用提议 + 执行结果）可被观测，提议可在执行前观测；
> **不经模型的动作、以及真实出站字节，本层不覆盖。**

「在检查范围」≠「会被检出」：`transform` 会把 `arguments` 里的命令字符串送进
PII 检测器，但 PII 检测器对无 PII 的命令原样透传。缺的是**行为规则**，不是检查范围。
