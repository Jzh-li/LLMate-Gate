## 0. 摘要：一句话定位与三条核心判断

**LLMate Gate 是一个运行在用户本机的、中文一等公民的、可测量可审计的 LLM 隐私网关。它拦截 Agent / IDE / 应用发往外部 LLM 的请求，在本地完成 PII 检测与脱敏，响应返回后在本地还原，让敏感信息不出本机。**

本方案建立在三个经反复推敲后不变的核心判断之上：

1. **代理为主，MCP 为辅**：透明代理覆盖 SDK 直连主流量，MCP Server 作为 v1.1 轻量占位，服务 MCP-first Agent 这一未来场景。
2. **壁垒在共享核心，不在门面**：中文格式保持仿真替换 + 可验证合规基准，才是竞品空白；门面（代理 / IDE / MCP）只是能力出口。
3. **集成而非训练**：直接集成 PII Engineer 的 Apache 2.0 检测能力，吸收 PrivAiTe 的代理架构、Kiji 的产品形态、Eidolon 的工程范式，不做从零训练。

差异化组合：**中文一等公民**（vs PrivAiTe 的 EN+FR 默认） + **仿真替换**（vs 竞品的占位符破坏语义） + **VS Code / Claude Code 原生零配置**（vs PII Engineer 的纯 API） + **可测量的审计证据链**（vs 所有竞品的 best-effort 话术）。

**品牌与分发**（详见 §14.1）：仓库 `llmate-gate`，GitHub 描述饱和覆盖"中文 LLM 隐私 / 仿真替换 / tool-call / 审计 / VS Code"关键词，Topics 标签 15+，发布后 1 周内做外部链接（掘金/知乎/Dev.to/HN）加速索引。目标：搜"中文 LLM 隐私网关""大模型 脱敏""LLM PII 中文"2-4 周内命中。

## 1. 问题与竞争格局

### 1.1 核心问题：Agent 时代的 PII 不只藏在 message 里

传统脱敏工具只扫 `message.content`，但 Agent 流量中 PII 无处不在：

- `tool_calls[].function.arguments`（JSON 参数值）
- 多模态内容（图片 OCR、文件解析结果）
- system prompt / 项目上下文（`CLAUDE.md`、`.cursorrules`）
- 上游 RAG 检索结果
- 配置文件、环境变量、日志行

**关键洞察**：Agent 每轮会把整段对话历史重发给 LLM。若不处理，PII 会随 tool_call、上下文文件、检索结果原样抵达供应商。**PrivAiTe 的核心创新正是"解析 tool-call JSON 逐值脱敏"**——实测竞品（LLM Guard、LiteLLM Presidio guardrail）在 tool-call 里 **100% 泄漏**，PrivAiTe 做到检测到的部分 100% 清除。这证明了"代理层必须理解 Agent 流量结构"。

### 1.2 竞争全景：赛道已经拥挤，空白在组合

经过对 GitHub 生态的系统调研，赛道可分为五层，各层均有成熟代表：

**① 高性能透明代理（最核心赛道）**

| 项目 | 语言 / 架构 | 强项 | 短板（我们的机会） |
|---|---|---|---|
| **PrivAiTe** | Python/FastAPI | tool-call 扫描、双引擎、可复现基准 `privaite-bench` | 默认 EN+FR、Python 性能、无 IDE/桌面、无审计 UI |
| **Kiji** | Go + Electron + ONNX | DistilBERT 仿真替换、macOS PAC 零配置、<100ms、**Dataiku 背书、402★** | **闭源、英文优先（6 语言）** |
| **Eidolon** | **Rust** + Axum + ONNX | 混合引擎、仿真替换、出口 DLP、自动路由、fail-closed | 无中文、无 IDE |
| **CloakPipe** | Rust | <5ms 开销、加密 vault、MIT | 无中文、无 IDE |
| **AI Privacy Gateway** | Python/FastAPI | **14+ 中国实体（身份证/手机/银行卡+Luhn）**、MIT、30 秒部署 | Python 性能、占位符为主 |
| **LLM-Shield-Proxy** | Python | **Tool Call AST-Aware 防火墙**、双管道、合规映射 | 无中文、性能一般 |
| **Redactr** | Go（3 静态二进制） | 四层管线、容器沙箱、团队控制面 | 过重，重心企业团队 |

**② 底层检测引擎**

| 项目 | 模型 | 语言覆盖 | 中文 |
|---|---|---|---|
| **PII Engineer** | GLiNER2（mDeBERTa-v3-base, 280M） | **50+** | **F1 0.918**、Apache 2.0、CPU 可跑 |
| **Kiji Model** | DistilBERT + 共指消解双头 | 6 种 | ❌ |
| **Microsoft Presidio** | spaCy NER + 正则 | 多（需下载模型） | 需自定义 |
| **cn_pii_anonymization** | 基于 Presidio 的中国大陆定制 | 中文 | ✅ |

**③ IDE / Agent CLI 原生集成**

- **leak-guard**：Claude Code 专用，Pre-tool hooks，.claude-plugin（检测能力依赖正则 + GitLeaks，中文弱）
- **PII Guardian / PromptGuard / Privacy Guard AI**：VS Code 扩展，本地高亮 / 改写 SDK 调用 / 保护 Copilot Chat
- **范式参考**：Tokligence（扩展自动起网关 + 配置 Continue/Cursor/Claude Code）、SafeGuard（扩展内起本地代理 + 远端网关纵深）、Cloq（启动自动代理 + prompt caching）

**④ MCP Server 形态（2026 新趋势）**

- **PII Anonymizer MCP**：Node.js，30+ 检测器，add_custom_names/patterns，stdio
- **SentinelMCP**：MCP 防火墙（工具白/黑名单 + 人环审批 + 审计），Apache 2.0
- **AgentGuard MCP**：联邦/国防级，NIST 800-53 / FedRAMP 合规映射
- **核心观察**：MCP 项目目前要么是"脱敏工具"要么是"管控网关"，**尚无"中文 + 仿真替换 + AST 感知"的组合**

**⑤ 仿真替换（Format-Preserving Fake）**

- Kiji（ML + Faker，英文）、Eidolon（Rust faker）、pii-proxy（正则）、nym（多策略）、Azure-Samples/llm-anonymizer（Faker 多 locale）
- **共识**：仿真替换的中文支持几乎为零——这是全行业的共同盲区

### 1.3 空白地带（已验证，本产品的落点）

**没有任何一个开源产品同时做到"中文一等公民 + 中文仿真替换 + IDE/Agent CLI 原生 + 合规审计 + 高性能守护进程"。** 具体三个独占空白：

1. **中文格式保持仿真替换**（唯一独占）：张三→李雷、13800138000→13900139000、身份证号带校验位——所有竞品均英文语境。
2. **三层一体 IDE/Agent 集成**：VS Code 扩展 + Claude Code hooks + 透明代理，竞品只做其中一层。
3. **cn-pii-bench 合规基准**：开源中文 PII 测评标准——对标 `privaite-bench`，是企业采购的信任锚。

## 2. 设计原则（不可妥协）

1. **Fail-closed**：检测引擎加载失败 / 调用超时 → **阻断请求，绝不静默放行**。crp4222 的所有项目（PrivAiTe、pmq）均贯彻此哲学（pmq 的 `PMQ_MCP_LIVE=1` 硬开关即典型），我们继承。
2. **可逆 ≠ 匿名化**：产品定性为 **pseudonymization + transfer minimization**。映射表仅在请求生命周期内驻留内存，响应返回后立即销毁，不落盘；审计日志另行加密存储，且需用户显式开启。
3. **可测量 > 可承诺**：绝不承诺"100% 防泄漏"。卖点是"在我这份数据上拦住 X%"，用 `cn-pii-bench` 脚本复现证明。这是 PrivAiTe 的信任锚，也是我们最值得借鉴的工程品格。
4. **零摩擦接入**：用户安装后无需改一行代码 / import，流量自动接管（借鉴 Kiji 的 macOS PAC + CloakPipe 的单二进制）。
5. **检测与代理解耦**：检测引擎可独立替换（规则 / PII Engineer / 自研模型 / cn_pii），代理层不受影响，实现统一 `Detector` 接口。
6. **中文一等公民**：默认加载中文 NER + 中文正则库，**而非事后加语言包**。

## 3. 架构演进：我们如何走到最终形态（决策记录）

> 本章忠实还原设计推敲过程——哪些方案被提出、为何被推翻。理解"走过的弯路"比只看终稿更重要。

### 3.1 起点：Rust 代理 + 分层检测（被推翻）

**初版方案**：用 Rust 写代理层，分层检测器（强模式实体走正则、中文走 NER、英文走 Privacy Filter），增量检测避免全量重扫。

**推翻理由**：
- **过度工程化**：Rust 代理的优化收益仅 10-20ms，但开发成本翻倍；PrivAiTe 的瓶颈是**检测引擎本身**（spaCy + ONNX），非 FastAPI 开销。
- **增量检测是伪需求**：历史里的 PII 已被替换，无需重新检测，只需缓存映射；真正要优化的是"新增 turn"的检测延迟。
- **忽略了 adoption**：架构最优但没人用等于零。

### 3.2 第二版：Go 代理 + PII Engineer sidecar（主导航）

**方案**：Go 守护进程调 PII Engineer 的 Rust server（HTTP :8000），VS Code 扩展做薄客户端。

**依据**：
- PII Engineer 已验证中文检测（F1 0.918、CPU 可跑、Apache 2.0、单二进制），无需自研；
- Go 跨平台单二进制、并发模型适合代理、<5ms 开销、开发效率高于 Rust；
- VS Code 扩展范式已被 Tokligence/SafeGuard 验证。

**此时锁定**：代理层语言 = **Go**，检测引擎 = **PII Engineer（Rust，直接集成不改）**，IDE = **TypeScript**。

### 3.3 关键外部输入：Kiji 改变了竞争格局

调研 `dataiku/kiji-proxy` 后发现：Kiji 已成熟验证"**仿真替换 + 桌面应用 + PAC 零配置 + 共指消解**"的商业可行性（Dataiku、402★、Apache 2.0、<100ms）。这迫使我们收缩代差主张：

- ~~"我们是唯一做仿真替换的"~~ → 改为 **"中文仿真替换"**（Kiji 做不到）；
- ~~"我们是唯一做桌面应用"~~ → 改为 **"三平台 + VS Code 原生"**；
- 核心代差收敛为 **中文一等公民 + IDE 原生 + 合规审计** 三件组合。

同时确认：Kiji 的 Go + Electron + ONNX 技术栈与我们的选型方向一致，印证架构合理。

### 3.4 MCP 之争：从"v1 同期必做"到"v1.1 占位"（重要推翻）

**初始判断**：把脱敏封装为 MCP Server，"AI Native"是趋势，应 v1 同期做。

**诚实检验**：逐条比对 MCP 与本地代理后，发现此前包装的"MCP 独占优势"多数不成立——

| 曾被归为"MCP 优势"的能力 | 验证结果 |
|---|---|
| 参数级差异化策略 | 代理解析 JSON 参数即可实现，**非独占** |
| 工具级白/黑名单 | 代理读 `tool_calls[].function.name` 即可，**非独占** |
| 字段级精准还原 | 代理持映射表 + 占位符位置，还原同样精准，**非独占** |
| **Agent 主动调用** | **唯一真优势**（代理只能被动拦截） |

**进一步判断**：MCP 的真实价值（Agent 主动脱敏）**完全取决于 Agent 是否 MCP-first**。而 2026 年主流仍是 **SDK 直连 + 透明代理**（Cursor、Continue、Claude Code、各类 Python Agent 框架），真正的 MCP-first Agent 仍是少数。

**最终决策**：MCP 降级为 **v1.1 轻量门面**。理由：
- 核心壁垒（中文仿真 + 审计）在**共享核心**，代理门面即可服务所有流量，MCP 对 v1 价值极小；
- v1 精力应砸在"中文仿真 + 透明代理 + VS Code 零配置 + 审计"这一竞品空白组合；
- 但必须占位（MCP 是协议趋势，复用核心仅需 3-5 天，是低成本未来期权）。

**这一决策避免了本末倒置**——把"多加一个 MCP 门面"误当成代差，而忽略真正无人覆盖的四件事组合。

### 4.3 内嵌调试面板（可观测性即产品）

> 完整规范见 `UI设计.md`；接口契约见 `接口与数据契约规范.md` §10。

**定位**：这不是"测试工具"，而是把 **可观测性直接做成产品**——借鉴 Kiji 的映射审查 UI，但更进一步做到"开箱即见流量 + Playground 即时测试"。

```
┌──────────────────────────────────────────────────────┐
│  门面层（:8400）                                      │
│  ┌────────────┐  ┌─────────────┐  ┌──────────────┐  │
│  │ 透明代理    │  │ IDE/hooks    │  │ MCP (v1.1)   │  │
│  └─────┬──────┘  └──────┬──────┘  └──────┬───────┘  │
│        │                │                  │           │
│        ▼                ▼                  ▼           │
│  ┌─────────────────────────────────────────────────┐    │
│  │  ★ 内嵌调试面板（Go embed + WebSocket）          │    │
│  │   GET /_debug     WS /ws/events                 │    │
│  │   POST /_api/detect   /_api/replace (本地,不上游) │    │
│  │  Tab: [流量] [Playground] [规则] [审计]         │    │
│  └─────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

**关键决策**：

1. **Go embed 内嵌单页**——`go:embed` 把 HTML/JS/CSS 打进单二进制，`go run .` 即开 `localhost:8400/_debug`，零依赖、零启动成本（**不做外置 Web 服务、不依赖 Tauri**）
2. **Phase 1 就做，不只给开发期**——它是即时测试工具 + 用户运维面板 + 售前演示载体三合一
3. **发布保留，可关闭**——默认 `debug: true`，`--no-debug` 彻底关闭（含 `/ws/events`、`/_api/*` 全返回 404）；仅绑定 `127.0.0.1`
4. **Playground 永不发请求到上游**——所有检测/替换/仿真都在本机完成，是"本地即时测试"的核心

**价值**：开发期验证 PII 检测、流式还原、仿真替换无需写 curl 脚本——面板里直接看原文 vs 脱敏 vs 还原的 5 段对比，把"调试体验"从命令行拉到可视化，开发效率质变。

## 5. 核心工作流（一条请求的完整生命周期）

```
Agent ──→ [① 解析请求体] ──→ [② 字段提取] ──→ [③ 分层检测 :8000]
                                      │
                                      ▼
                              [④ 脱敏 + 建映射表]
                                      │
                                      ▼
                            [⑤ 转发脱敏请求] ──→ 上游 LLM
                                      │
                                      ▼
                            [⑥ 响应还原（流式逐 token）]
                                      │
                                      ▼
                            [⑦ 销毁映射表 + 写审计日志]
                                      │
                                      ▼
                                返回 Agent
```

**字段提取规则**（对齐 PrivAiTe，明确扫与不扫）：
- ✅ 扫：`messages[].content`（含多模态文本）、`tool_calls[].function.arguments`（JSON 值）、`/v1/completions` 的 prompt/suffix、`/v1/embeddings` 的 input、`prediction.content`、`web_search_options.user_location`、响应里的 reasoning/refusal/audio_transcript/返回 tool_calls
- ❌ 不扫（v1，需明文告知用户）：`messages[].name`、顶层 user/metadata、`tools` 定义、JSON 键、tokenized 整数数组、本地 Agent 上下文（Claude Code/Codex 本地仍持真实值——这是代理架构的固有边界）

**实体命运（per-type fate）**：

| 实体类型 | 默认命运 | 说明 |
|---|---|---|
| `CREDIT_CARD` / `BANK_ACCOUNT` | mask（保留后 4 位） | 可部分还原用于展示 |
| `SECRET` / `API_KEY` / `PRIVATE_KEY` | **redact（永久丢弃）** | 不可逆，响应中也抹除 |
| `PERSON` / `EMAIL` / `PHONE` / `ADDRESS` / `DATE` | reversible placeholder | 响应中还原 |
| `ID_CARD` / `PASSPORT` / `MEDICAL_RECORD` | mask 或 redact（按策略） | 高敏感，默认 redact |

**流式还原**：使用 trie 缓冲占位符跨 SSE 块还原，保证占位符与映射表严格一一对应（借鉴 PrivAiTe，避免跨块错位）。

## 6. API 契约与占位符协议

> 本章定义三个接口契约：**① Go 代理 ↔ PII Engineer 的检测协议；② 占位符命名规范；③ Go 代理对外暴露的 OpenAI 兼容端点**。契约稳定后，各模块可并行开发。

### 6.1 Go 代理 ↔ PII Engineer（本机 HTTP :8000）

PII Engineer 原生提供 `POST /api/detect`，请求/响应契约如下（基于其官方 server 实现）：

**请求**：
```json
POST http://127.0.0.1:8000/api/detect
Content-Type: application/json

{
  "text": "张三的手机号是13800138000，身份证110101199001011234",
  "language": "zh",
  "threshold": 0.5
}
```

**响应**：
```json
{
  "entities": [
    {
      "type": "zh_person_name",
      "value": "张三",
      "start": 0,
      "end": 2,
      "score": 0.96
    },
    {
      "type": "zh_phone",
      "value": "13800138000",
      "start": 8,
      "end": 19,
      "score": 0.99
    },
    {
      "type": "zh_id_card",
      "value": "110101199001011234",
      "start": 24,
      "end": 42,
      "score": 0.98
    }
  ],
  "redacted": "<<zh_person_name_1>>的手机号是<<zh_phone_1>>，身份证<<zh_id_card_1>>"
}
```

**关键约定**：
- Go 代理按**字符偏移 `[start, end)`** 切分原文，逐段替换，避免正则回溯灾难；
- `score >= threshold` 才脱敏，阈值按实体类型差异化配置（人名 0.5、身份证 0.8——强格式实体阈值更高以减少误报）；
- **批量接口**：`POST /api/detect/batch` 一次传入多条文本（tool_call 多参数场景），减少 HTTP 往返；
- **超时与熔断**：调用检测引擎超时 **500ms** 即触发 fail-closed 阻断；使用熔断器（hystrix 模式），连续 5 次失败后进入半开态探测；
- **进程管理**：Go 代理启动时自动拉起 PII Engineer sidecar（`exec.Command`），监听其健康检查 `GET /healthz`，sidecar 崩溃自动重启，最多 3 次。

### 6.2 占位符协议（Placeholder Protocol）

占位符是代理与 LLM 之间传递的"假名"，映射表是本地还原的依据。**协议一旦定下不可随意变更**（影响审计日志可读性）。

**格式**：`<<{entity_type}_{index}>>`，例如 `<<zh_person_name_1>>`、`<<email_3>>`。

**规则**：
1. **同实体同值 → 同占位符**：全文（同一请求）内"张三"始终映射为 `<<zh_person_name_1>>`，保证 LLM 能建立跨句指代关系（这是占位符优于随机 mask 的关键）；
2. **不同类型即使值相同 → 不同占位符**：身份证号"110101..."与人名"110101"不会冲突（type 区分）；
3. **index 按类型独立计数**：`zh_person_name_1`、`zh_person_name_2`……`email_1`、`email_2`……；
4. **流式 trie 还原**：SSE 分块到达时，用 trie 树缓冲不完整的占位符前缀（如收到 `<<zh_person_na`），跨块拼接完整后再查映射表还原，杜绝"半个占位符"泄漏；
5. **保留原始偏移**：映射表额外记录占位符在脱敏文本中的 `[start, end)`，响应还原时按偏移精准替换，而非字符串 `ReplaceAll`（避免正文里恰好出现 `<<...>>` 被误还原）。

**映射表结构**（内存，AES-256-GCM 加密）：
```go
type MappingTable struct {
    RequestID      string
    ConversationID string    // 绑定会话，用于 detection_cache
    Entries        []MappingEntry
    CreatedAt      time.Time
    TTL            time.Duration // 默认 30m
}

type MappingEntry struct {
    Placeholder string // "<<zh_person_name_1>>"
    Original    []byte // 明文，敏感
    EntityType  string // "zh_person_name"
    Score       float32
    Fate        Fate   // Reversible / Mask / Redact
    // 仿真替换专用（v1.1）：
    FakeValue   []byte // "李雷"（响应还原时直接用，无需再查原值）
}
```

### 6.3 对外端点（OpenAI 兼容）

Go 代理在 `:8400` 暴露以下端点，Agent / SDK **零代码改动**即可接入（仅改 `base_url`）：

| 端点 | 说明 | 是否流式 |
|---|---|---|
| `POST /v1/chat/completions` | Chat 主端点（GPT 系列） | ✅ SSE |
| `POST /v1/completions` | 补全（legacy） | ✅ SSE |
| `POST /v1/embeddings` | 向量化（input 也脱敏） | ❌ |
| `POST /v1/responses` | OpenAI Responses API | ✅ SSE |
| `POST /v1/messages` | Anthropic Claude（路径转换） | ✅ SSE |
| `GET  /v1/models` | 透传模型列表 | ❌ |
| `GET  /healthz` | 网关健康检查（含 sidecar 状态） | ❌ |
| `GET  /metrics` | Prometheus 指标 | ❌ |

**协议转换**：`/v1/messages`（Anthropic）与 `/v1/chat/completions`（OpenAI）在代理层做双向字段映射，让同一份脱敏逻辑同时服务两类 SDK（参考 Tokligence 的协议互转）。

## 7. 中文格式保持仿真替换引擎（独占代差 #1）

> 占位符 `<<zh_person_name_1>>` 会破坏 LLM 上下文（模型看到的是无意义 token，长期记忆/指代消解能力下降）。**仿真替换用"格式语义一致的假数据"替代占位符**，是 LLMate Gate 相对所有竞品的独占代差。本章定义 v1.1 的实现规则。

### 7.1 设计原则

1. **格式一致**：身份证号必须是 18 位且校验位合法；手机号符合号段；银行卡通过 Luhn 校验；
2. **语义一致**：人名性别/字数与原值一致（"欧阳娜娜"→"司马文文"，复姓→复姓）；地址逆向结构一致；
3. **会话内双射**：同一请求生命周期内，`f(张三) = 李雷` 恒成立，确保 LLM 跨句指代不崩；
4. **不可逆但可还原**：默认用 HMAC-SHA256（密钥 = 会话密钥 + entity_type）派生仿真值，**相同输入恒产生相同输出**，天然实现双射且不存明文映射（可选：仍保留映射表以支持审计）；
5. **代码/配置安全**：代码字符串、JSON key、路径中的 PII 必须走仿真（占位符会破坏语法），见 §14 风险第 5 条。

### 7.2 各实体仿真规则

| 实体类型 | 规则 | 示例（原 → 假） |
|---|---|---|
| `zh_person_name` | Faker zh + 姓氏库 + 性别对齐；复姓识别 | 张三 → 李雷；欧阳娜娜 → 司马文文 |
| `zh_phone` | 号段合法（13x/14x/15x/17x/18x/19x）+ 后 8 位随机但校验 | 13800138000 → 13900139000 |
| `zh_id_card` | 前 17 位合法行政区划+生日+顺序码，第 18 位按 ISO 7064 加权校验 | 110101199001011234 → 310101199501011234（校验位重算） |
| `zh_bank_card` | 6 位 BIN（银行标识）+ Luhn 校验 | 6222021234567890123 → 6228481234567890123 |
| `zh_address` | 逆向生成：省→市→区→街道→门牌，库取自公开行政区划 | 北京市海淀区中关村大街88号 → 上海市浦东新区世纪大道100号 |
| `email` | 保留域名结构，本地部分哈希派生 | zhang.san@example.com → li.lei@example.com |
| `ip_address` | 保留私网/公网类别，子网内派生 | 192.168.1.100 → 192.168.1.201 |
| `date` | 保留相对关系（如"明天"→"明天"的仿真日期） | 1990-01-01 → 1995-05-05 |
| `amount` | 金额按比例缩放（可选）或同数量级替换 | ¥12,500 → ¥8,300 |

### 7.3 身份证校验位算法（关键，必须正确）

```go
// ISO 7064 / GB 11643 加权校验
func idCardChecksum(body17 string) byte {
    weights := []int{7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2}
    checkMap := "10X98765432"
    sum := 0
    for i, c := range body17 {
        sum += int(c-'0') * weights[i]
    }
    return checkMap[sum%11]
}
// 生成：先随机前 17 位（符合行政区划），再算第 18 位
```

> ⚠️ 仿真身份证号**仅用于脱敏展示，绝不对应真实自然人**（行政区划用公开的省级代码，顺序码避免特定敏感值）。任何情况下不得用生成的号码做真实身份核验。

### 7.4 与占位符模式的切换

- **v1**：默认占位符模式（稳定、无语义损失风险），仿真替换作为可选实验开关；
- **v1.1**：默认仿真替换（经基准验证 LLM 输出质量无损后切换），占位符降级为"不可逆 redact"场景（如 SECRET）；
- **切换依据**：用 `cn-pii-bench` 对比两种模式下 LLM 输出质量（见 §13.2）。

## 8. 安全模型（威胁模型 + 攻击面）

> LLMate Gate 的定位是 **pseudonymization（假名化）+ transfer minimization**，不是 anonymization。本章明确"防什么、不防什么"，避免安全夸大。

### 8.1 威胁模型（在范围内）

| 威胁 | 防护手段 |
|---|---|
| **上游 LLM 供应商数据留存/滥用** | 出站前脱敏，供应商只见仿真值 |
| **中间链路嗅探**（企业内网、代理链） | TLS 转发 + 本地映射表不随请求外出 |
| **可观测性系统 PII 泄露**（Langfuse/ELK/Grafana 记录原始 prompt） | 日志管线接入 LLMate Gate，记录的是脱敏后文本 |
| **模型输出复述 PII** | 响应侧扫描（v1.1 出口 DLP，参考 Eidolon），还原仅在客户端 |
| **恶意依赖/工具调用泄露** | tool-call 参数扫描 + 工具白名单（参考 Redactr 容器沙箱） |
| **检测引擎单点故障导致裸奔** | fail-closed 默认阻断 |

### 8.2 攻击面（明确告知用户，不在范围内）

1. **本地攻击者读取映射表**：映射表驻留内存，本机恶意进程理论上可 dump。缓解：AES-256-GCM 加密（密钥来自 OS keychain），TTL 缩短至请求生命周期；
2. **检测漏报**：中文 `person_name` F1 ≈ 0.823，复杂语境（诗歌、古风文、少数民族姓名、港澳台拼写）会漏。缓解：`cn-pii-bench` 量化 + 用户自定义规则；
3. **上下文推断攻击**：即使姓名被替换，"他住在北京市海淀区"仍可结合外部信息反推。缓解：地址也脱敏 + 提供"严格模式"扫 JSON 键；
4. **LLM 侧信道**：模型可能在 few-shot 中记忆 PII。**这是代理架构的固有边界**——LLMate Gate 只保护出网那段，不控制模型记忆；
5. **不扫字段**：`messages[].name`、顶层 metadata、`tools` 定义、JSON 键、tokenized 整数数组、本地 Agent 上下文（Claude Code/Codex 本地仍持真实值）。v1.1 提供"严格模式"可选扫 JSON 键；
6. **供应链**：PII Engineer 依赖树、Go 模块、Tauri 前端依赖。缓解：锁定版本 + SBOM + 签名发布。

### 8.3 映射表加密方案

```
会话密钥 = HKDF(masterKey, conversationID || requestID)
masterKey 来源：首次启动生成并存于 OS keychain
                （macOS Keychain / Windows DPAPI / Linux secret-service）

每个 MappingEntry：
  ciphertext = AES-256-GCM(plaintext, sessionKey, nonce=random)
  stored = nonce || ciphertext || tag
```

**审计日志与映射表分离**：审计日志默认**关闭**且需用户显式开启，开启后落盘用 SQLCipher（AES-256）加密——避免"脱敏"反而成为数据聚集点。

### 8.4 合规映射（产品化合规报告的依据）

| 法规/框架 | LLMate Gate 提供的控制 | 报告字段 |
|---|---|---|
| **GDPR** Art. 5/32（完整性保密、安全处理） | 加密映射表、fail-closed、审计日志 | 处理活动记录、安全措施说明 |
| **PIPL**（个人信息保护法） | 最小化传输、去标识化、出境前脱敏 | 出境风险评估辅助材料 |
| **等保 2.0** | 访问控制、安全审计、数据加密 | 等保测评项对照 |
| **HIPAA Safe Harbor** | 18 类标识符脱敏 | 去标识化认证 |

> ⚠️ 使用 LLMate Gate **不自动构成合规**。它只是纵深防御的一环，需结合注入检测、内容审计、数据出境评估。合规结论须由法务确认。

### 9.2 测评指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **实体召回率（Entity Recall）** | 检测到的标注实体 / 总标注实体 | ≥ 85% |
| **严格召回率（Strict Recall）** | 边界完全匹配（偏移误差 ≤1）的占比 | ≥ 80% |
| **误报率（False Positive）** | 假阳性实体 / 总检测实体 | < 5% |
| **F1** | 2·P·R/(P+R) | ≥ 0.88 |
| **延迟 p50/p95/p99** | 单条检测 + 代理开销 | p50 < 200ms, p99 < 2s |
| **tool-call 泄漏率** | tool_call 参数中仍泄露的 PII 占比 | 0%（检测到的部分 100% 清除） |

> **§9 实现状态（2026-09-10）**：本节指标已在 `bench/runner.py`（L1 检测器级）和
> `bench/carriers.py`（L2 泄漏级，含 4 载体对等性 + 往返）中落地。详细规范见
> `Specs/03-测试规约.md` §4.3（含双层口径、载体对等性、harness 自检、第三方标注硬约束）。

| 延迟 | MacBook M 系列 FP32 ~150ms p50；4 vCPU AMD INT8 ~250ms；8 vCPU AMD INT8 ~180ms p50 |
| 吞吐 | ~5 req/s（单实例） |
| GPU | **非必须**（CPU 即可，高并发才考虑 GPU） |

> 官方结论：**4 核 8GB VPS（$42/月档）即可扛一个小团队流量，no external API calls。**

### 10.2 推荐硬件档位

| 档位 | 配置 | 用途 |
|---|---|---|
| 最低 | 2 核 / 4GB RAM / 1GB 磁盘 | 开发验证、个人本机 |
| **推荐（甜点）** | **4-8 vCPU / 8GB RAM** | **开发者本机 / 小团队网关，~180ms p50** |
| 生产 | 16+ vCPU / 32GB RAM | 团队/企业，多实例 + LB |

### 10.3 单请求延迟预算（Agent 场景）

| 环节 | 耗时 |
|---|---|
| 代理转发 | <5ms（Go，对标 CloakPipe <5ms） |
| PII 检测（PII Engineer INT8） | ~180ms |
| 映射表读写 | <1ms |
| **总计增加** | **~185ms** |
| 云端 LLM 基线 | 1000-5000ms |
| **占比** | **3.7%-18.5%（可接受）** |

> **⚠️ §10 状态澄清（2026-09-11）**：本节规格（PII Engineer 280M 模型 / 620MB / 800MB 内存 / 180ms p50）描述的是**如果启用 PII Engineer** 的资源消耗。
> **v0.1 实际并未启用**——当前 `detection.engine=regex`（内置中文正则 + 校验位）跑全量请求，
> 原因：`30c9de0` 后合成语料 F1=1.0、p99=23ms，集成 ROI = 0。
> 二进制 ~10MB（stripped）/ 启动 < 1 秒 / 内存 ~30MB 的**轻量特性是设计优势**——
> PII 形态学问题（身份证校验位 / 手机号段 / Luhn / 邮箱格式）用正则 100% 召回，
> 根本不需要模型推理。PII Engineer sidecar 的**重启条件**是「真实对抗语料召回率 < 85%」
> （见 `Specs/03-测试规约.md` §4.3.4 第三方标注硬约束）。
> 用户提问「LLM 本地判断隐私 / 文件那么小不用加载本地模型吗」的答案：
> **没有 LLM 判断；regex 已经够用；文件小是设计而非遗漏。**

**Agent 多轮优化**：必须默认开启 `detection_cache`（Merkle 增量，缓存键绑定 `conversation_id`，避免跨会话错乱）。参考 PrivAiTe 实测——不开缓存时 Claude Code 峰值 **42 秒/请求**、Codex **72 秒/请求**；开启后中位 1-3 秒。LLMate Gate 目标：**P99 < 2s**（§6.3 占位符协议规定缓存键必须会话隔离）。

> ⚠️ **2026-09-10 实现状态标注（原文要求保留，仅加注）**：

| 模块 | 选型 | 理由 |
|---|---|---|
| **代理层** | **Go** | 跨平台单二进制、并发模型天然适合代理、<5ms 开销、开发效率高于 Rust；Eidolon/CloakPipe 已验证高性能代理可行 |
| **检测引擎** | **PII Engineer（Rust/ONNX，直接集成）** | Apache 2.0、中文 F1 0.918、CPU 可跑、已有 Rust server；**不从零训练** |

| **仿真替换** | Go（规则生成 + Faker zh + 校验位） | 格式保持、中文原生、高性能；v1.1 评估是否引入小模型 |
| **进程间通信** | 本机 HTTP（:8000） | 简单；未来可换 gRPC / Unix socket 降延迟 |
| **映射表** | 内存 + AES-256 + TTL | 请求生命周期，不落盘 |
| **桌面 UI** | **Tauri**（前端 TS + 后端 Rust） | 几 MB、跨平台、Rust 后端（Kiji 用 Electron，我们选更轻的 Tauri） |
| **IDE 集成** | **VS Code 扩展（TypeScript）** + **Claude Code hooks** | 薄客户端 + 自动配置（参考 Tokligence / leak-guard） |
| **MCP Server** | **v1.1，官方 TS SDK**（薄门面） | 复用共享核心，3-5 天，占位 MCP-first 趋势 |
| **许可证** | **Apache 2.0** | 商用友好、含专利授权（优于 PrivAiTe 的 BSD-3） |

**语言分工清晰**：Rust 只负责检测引擎（PII Engineer 已有）+ 桌面 UI 后端（Tauri 生成）；Go 只负责代理层；TypeScript 只负责 VS Code 扩展 + 桌面前端。**三者无重叠、无不必要的复杂度。**

> ⚠️ **许可证传染防护**：PII Engineer 为 Apache 2.0，可静态链接并闭源分发（保留版权声明即可）。若未来接入 AGPL 组件（如部分 gliner 衍生模型），须隔离为独立进程，避免传染主项目。

## 14. 必须守住的风险边界

> 安全模型的完整威胁分析见 §8。此处列出执行层必须遵守的硬约束。

1. **这是假名化，不是匿名化**：检测 best-effort，映射表在内存中，本地攻击者理论上可获取。**绝不在营销中承诺"100% 防泄漏"**——继承 PrivAiTe 的诚实品格（§8.1/§8.2 详列威胁与攻击面）。
2. **不扫字段需明文告知**：`messages[].name`、顶层 metadata、`tools` 定义、JSON 键、tokenized 数组、本地 Agent 上下文。v1.1 提供"严格模式"可选扫 JSON 键。
3. **中文 `person_name` F1 ≈ 0.823**（非 0.918 均值），复杂语境会漏报——用 `cn-pii-bench` 量化后决定是否微调（§9）。
4. **detection_cache 默认开启**，且缓存键绑定 conversation_id，否则 Agent 多轮 40s+（§6.3 占位符协议规定缓存键必须会话隔离）。
5. **占位符破坏代码结构**：代码/配置场景 v1.1 切仿真替换，避免 `[PERSON_1]` 破坏语法（§7）。
6. **上游 LiteLLM 供应链风险**：若集成 LiteLLM guardrail，锁定安全版本（2026-03 曾发生投毒事件）。
7. **映射表持久化策略**：默认请求生命周期销毁；审计日志需用户显式开启且加密（SQLCipher AES-256），避免"脱敏"反而成为数据聚集点（§8.3 加密方案）。
8. **仿真身份证号绝不对应真实自然人**：行政区划用公开省级代码，顺序码避免特定敏感值（§7.3）——生成的号码仅用于脱敏展示，不得做真实身份核验。
9. **可观测性不泄露明文**：Prometheus `/metrics` 只暴露计数/延迟直方图，**绝不暴露原始 PII**；日志默认脱敏。

## 附录 A：竞品关键事实速查

- **PrivAiTe**（`crp4222/PrivAiTe`）：双引擎（Presidio + OpenAI Privacy Filter ONNX），tool-call 扫描核心差异化，120 篇真实文档基准 onnx 召回 84.5%、tool-call 泄漏 15.5%，默认 EN+FR，BSD-3，v0.4.2。
- **Kiji**（`dataiku/kiji-proxy`）：Dataiku 575 Lab，INT8 DistilBERT（26 类、F1 0.94、<100ms）+ 共指消解双头、格式保持仿真替换、macOS PAC 零配置、Electron 桌面、402★、Apache 2.0、**英文优先（6 语言）**。
- **Eidolon**（`0M3REXE/eidolon`）：Rust + Axum + ONNX，混合引擎、仿真替换、出口 DLP、自动路由、fail-closed，Apache 2.0——**架构标杆**。
- **AI Privacy Gateway**（`gunxueqiu6/ai-privacy-gateway`）：中文竞品，14+ 中国实体 + 校验位、MIT、30 秒部署——**中文正则标杆**。
- **LLM-Shield-Proxy**：Tool Call AST-Aware 防火墙、双管道（Human/Machine）、STATELESS_CRYPTO——**AST 感知参考**。
- **PII Engineer**：GLiNER2/mDeBERTa-v3-base/280M，50+ 语言，中文 F1 0.918，INT8 encoder，~800MB RAM，无需 GPU，Apache 2.0，Rust server——**检测引擎首选**。
- **cn_pii_anonymization**：基于 Presidio 的中国大陆定制——**中文补充**。
- **CloakPipe**：Rust 代理 <5ms、加密 vault、MIT——**性能标杆**。
- **Redactr**：Go 三二进制、四层管线、容器沙箱——**企业架构参考**。
- **leak-guard**：Claude Code Pre-tool hooks——**hooks 范式参考**。
- **Tokligence / SafeGuard / Cloq**：VS Code 扩展自动起本地代理 + 配置 Continue/Cursor/Claude Code——**IDE 集成范式参考**。

## 附录 B：术语

- **Pseudonymization（假名化）**：用占位符/假名替换，可通过映射表还原。本产品属此类。
- **Anonymization（匿名化）**：不可逆，无法还原。本产品**不做**。
- **Transfer minimization**：最小化传输给第三方的原始数据量。
- **Fail-closed**：组件故障时默认拒绝/阻断，而非放行。
- **Format-preserving fake**：生成格式与语义一致的仿真值（如张三→李雷），LLM 无感知。
- **Detection cache**：对扫描过的文本片段哈希缓存检测结果，避免 Agent 多轮全量重扫；缓存键绑定 conversation_id。
- **AST-Aware 脱敏**：理解 JSON / 工具调用结构，按键义差异化处理（区别于盲扫文本）。
- **MCP (Model Context Protocol)**：Agent 工具调用标准协议；本产品中作为 v1.1 轻量门面，非核心战场。

## 附录 C：决策记录（重要结论的时间线）

| 决策 | 结论 | 理由（一句话） |
|---|---|---|
| 是否自研中文模型 | **否，集成 PII Engineer** | 已有 Apache 2.0 成熟模型，训练成本高且非壁垒 |
| 代理层语言 | **Go**（非 Rust、非 Python） | 性能足够 + 开发效率最优；Rust 留给检测引擎 |
| 是否做仿真替换 | **是，且聚焦中文** | Kiji/Eidolon 已证明英文可行，中文是空白 |
| 是否做 IDE 原生 | **是，VS Code + Claude Code** | 竞品只做其中一层，三层一体是组合空白 |
| 是否做合规基准 | **是，cn-pii-bench** | 对标 privaite-bench，是企业采购信任锚 |
| MCP 是否 v1 同期 | **否，降到 v1.1** | 唯一真优势是"Agent 主动调用"，当下主流是 SDK 直连，MCP 是未来期权 |
| 核心壁垒在哪 | **共享核心，非门面** | 中文仿真 + 审计基准放代理层即可服务所有流量 |
| 产品名为何从 PII Guard 改为 LLMate Gate | **传达"为大模型设计"** | 抽象名不利于搜索发现；"LLMate"直指 LLM 生态，"Gate"明确网关形态（§13.1） |
| 占位符 vs 仿真替换 | **v1 占位符，v1.1 仿真** | 先用稳定占位符出 MVP，验证中文仿真不损 LLM 输出质量后再切换（§7.4） |
| **是否做内嵌调试面板（类 Kiji）** | **是，Phase 1 就做，发布保留** | Go embed 单页 + WebSocket，零依赖；Playground 本地即时测试（不上游）；`--no-debug` 可关。既是开发加速器，也是可观测性产品差异化（§4.3、`UI设计.md`） |
