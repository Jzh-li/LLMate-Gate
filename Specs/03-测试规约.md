## 1. 单元测试规范

### 1.1 通用规则

- 测试文件：`xxx_test.go`，与被测文件同包
- 命名：`Test<函数名>_<场景>`（PascalCase）
- 使用 `testify/require` 做断言；使用 `gomock` / `testcontainers-go` mock 外部依赖
- **每个导出的函数必须有至少 1 个正向 + 1 个异常用例**

### 1.2 Mock 约定

| 真实依赖 | Mock 方式 | 存放 |
|---|---|---|
| PII Engineer sidecar | `httptest.Server` 返回预设 JSON | `detector/detector_mock_test.go` |
| Vault 持久化 | 内存实现 `memVault` | `vault/mem.go`（仅测试构建） |
| 上游 LLM | `httptest.Server` 回显请求 | `proxy/proxy_test.go` |

**Mock 响应 fixture**（`testdata/detector/`）：

```json
{ "entities": [{"type":"zh_person_name","value":"张三","start":0,"end":6,"score":0.97}], "latency_ms": 180 }
{ "entities": [], "latency_ms": 10 }
{ "error": "timeout" }
```

### 1.3 关键测试清单（必须全部存在）

#### detector

- [ ] `TestDetect_Success`：正常返回实体列表，按 `start` 升序
- [ ] `TestDetect_Timeout`：超过 500ms → `ErrDetectorTimeout`
- [ ] `TestDetect_SidecarDown`：sidecar 不可用 → `ErrDetectorUnavailable`
- [ ] `TestDetect_Threshold`：score 低于阈值 → 不返回该实体
- [ ] `TestDetectBatch_Order`：批量结果顺序与输入一致

#### replacer

- [ ] `TestReplace_DoubleMapping`：同值同占位符（"张三"→`_1` 两次）
- [ ] `TestReplace_DiffTypeSameValue`：身份证与人名值相同 → 不同占位符
- [ ] `TestReplace_OffsetPreserved`：占位符在脱敏文本中的偏移正确
- [ ] `TestRestore_ByOffset`：正文恰含 `<<x>>` 不被误还原（按偏移）
- [ ] `TestStreamRestore_Trie`：SSE 分块跨块拼接占位符，完整还原
- [ ] `TestStreamRestore_Orphan`：流结束仍有不完整占位符 → metric + 保留原样

#### simulator

- [ ] `TestIDCard_Checksum`：生成号码第 18 位通过 ISO 7064 校验
- [ ] `TestIDCard_NoRealPerson`：生成号码不对应真实行政区划+生日组合（统计 1000 个）
- [ ] `TestPhone_Prefix`：生成号码前缀在合法号段内
- [ ] `TestBankCard_Luhn`：生成号码通过 Luhn 校验
- [ ] `TestDoubleMapping`：同会话 `f(name,张三)` 恒定
- [ ] `TestIrreversible_Redact`：`api_key`/`password`/`token` 走 redact，无仿真值

#### vault

- [ ] `TestSealUnseal_RoundTrip`：序列化→加密→解密→反序列化，字段一致
- [ ] `TestTTL_Expired`：过期后 `Get` → `ErrNotFound`
- [ ] `TestMemzero`：明文 `Original` 处理后为零（通过反射检查）

#### cache

- [ ] `TestCache_ConversationBound`：不同 conversation_id 同文本 → 不命中
- [ ] `TestCache_TTL`：过期后需重新检测

#### config

- [ ] `TestConfig_Valid`：合法 YAML 加载成功
- [ ] `TestConfig_MissingUpstream`：必填缺失 → exit(2)
- [ ] `TestConfig_EnumInvalid`：非法 strategy → 校验错误

#### audit

- [ ] `TestAudit_NoPIIByDefault`：默认日志不含 `sample_text`
- [ ] `TestAudit_Export_PIP`：导出字段符合 PIP 要求

## 2. 集成测试规范

### 2.1 detector + replacer + vault

**场景**：完整替换链路（不走 HTTP）。

```go
func TestIntegration_ReplaceAndRestore(t *testing.T) {
    // 1. 启动 httptest mock detector
    // 2. 构造 Replacer（依赖 vault + detector）
    // 3. Replace("张三的手机号是13800138000") → "<<zh_person_name_1>>..."
    // 4. Restore(脱敏文本) → 原文完全一致
    require.Equal(t, orig, restored)
}
```

**断言标准**：

- `restored == original`（字节级完全一致）
- 映射表条目数 == 检测实体数
- 占位符在脱敏文本中按偏移可定位

### 2.2 proxy + detector（流式）

**场景**：上游返回 SSE 流，代理逐块还原。

**断言标准**：

- 客户端收到的完整流 == 原始响应中占位符被还原后的结果
- 流中**不出现**任何 `<<...>>` 占位符（还原完整率 100%）
- 内存峰值 < 1MB（不缓存整个流）

### 2.3 fail-closed

**场景**：detector 返回 503 / 超时。

**断言标准**：

- 请求被 **阻断**，返回 `502 detector_timeout`
- **不得**将原文转发给上游（这是安全红线）
- 审计日志记录 `outcome: blocked`

## 3. 端到端测试（E2E）

### 3.1 拓扑

```
curl/SDK → llmate-gate(:8400) → mock LLM server(:9000)
                  │
                  └── PII Engineer sidecar(:8000, testcontainers)
```

### 3.2 测试矩阵（必须全绿）

| # | Agent 行为 | 上游 | 流式 | 断言 |
|---|---|---|---|---|
| E1 | Chat 请求含中文 PII | 回显脱敏文本 | ❌ | 上游收到占位符/仿真值；客户端收到原文 |
| E2 | Chat 请求含 tool_calls PII | 回显 | ❌ | `arguments` 中的 PII 被替换 |
| E3 | 响应含占位符 | 返回占位符文本 | ✅ SSE | 客户端流中占位符被还原 |
| E4 | 多轮（同 conversation_id） | 回显 | ❌ | 第二次请求走缓存，延迟 < 50ms |
| E5 | detector 超时 | mock 慢响应 | ❌ | 返回 502，原文**不**泄露 |
| E6 | Anthropic `/v1/messages` | Claude 格式回显 | ✅ | 协议转换正确，脱敏生效 |
| E7 | 无效 auth | — | ❌ | 401 unauthorized |
| E8 | embeddings input 含 PII | 回显 | ❌ | input 被脱敏 |

### 3.3 E2E 脚本模板

```bash
#!/bin/bash
# e2e/e2e.sh
set -e
export GATEWAY_AUTH_TOKEN=test-token
go run ./cmd/llmate-gate &  # PID=...
trap "kill $PID" EXIT

# 等待 healthz
until curl -s localhost:8400/healthz; do sleep 0.5; done

# E1: 中文 PII 替换
resp=$(curl -s -X POST localhost:8400/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_AUTH_TOKEN" \
  -d '{"model":"gpt-4","messages":[{"role":"user","content":"联系张三13800138000"}]}')
echo "$resp" | grep -q "13800138000" && { echo "FAIL: PII leaked"; exit 1; } || echo "PASS E1"
```

### 4.3 测评指标

| 指标 | 定义 | v1 门槛 |
|---|---|---|
| **召回率 Recall** | 检出的 GT 实体 / 全部 GT 实体 | **≥ 85%** |
| **精确率 Precision** | 检出的正确实体 / 全部检出 | ≥ 90% |
| **F1** | 2·P·R/(P+R) | ≥ 0.88 |
| **偏移准确率** | start/end 完全正确的占比 | ≥ 95% |
| **tool-call 覆盖率** | 参数中被扫描的参数占比 | 100% |
| **仿真格式合法率** | 生成的身份证/手机/银行卡通过校验的比例 | 100% |
| **P99 延迟** | 单条检测 + 替换 | < 2s（含缓存 < 50ms） |

> **⚠️ 4.3 更新（2026-09-10，借鉴 privaite-bench）**：上面这套门槛在**自作者合成语料**上自评是**自证**——F1 高只说明「检测器与生成器对同一套仿真规则达成一致」，**不构成真实场景结论**。
> 凡是用于对外宣称或决策门（GO/PIVOT）的数字，必须满足 §4.3.4「第三方标注硬约束」。

#### 4.3.1 双层口径（为什么要分两层）

| 层 | 文件 | 输入 | 比较对象 | 抓的什么洞 |
|---|---|---|---|---|
| **L1 检测器级** | `bench/runner.py` | 文本 | 检测器返回的 span 四元组 | 漏检、错检、偏移错 |
| **L2 泄漏级** | `bench/carriers.py` | 4 种 OpenAI 消息载体（`flat` / `multimodal` / `tool_call` / `tool_call_nested`） | 脱敏后 JSON 文本中 PII 字符串是否还在 | 替换/递归/还原链路、PII 透出上游 |

F1=1.0 只过 L1 不够；如果 L2 有 regression，**PII 真就漏给上游 LLM 了**。
L2 是 L1 兜不住的「端到端」层级，借鉴 privaite-bench `bench_structured.py` 的思想。

#### 4.3.2 载体对等性（carrier parity）

- 4 种载体（`CARRIERS`）：`flat` / `multimodal` / `tool_call` / `tool_call_nested`。
- 调用 `POST /v1/privacy/redact`（键保留、任意嵌套 JSON 递归脱敏），把同一段 PII 文本重新包裹。
- 指标：
  - `anonymized` / `leaked`（PII 原串是否还出现在脱敏后 JSON 的扁平化文本里）
  - `regressions vs flat`：flat 能脱的、载体必须能脱。**目标 0。**
  - `round-trip`：`POST /v1/privacy/restore` 后每个被脱敏的 PII 必须无损回来。
- 守门模式：`python3 bench/carriers.py --gate`；regression > 0 或往返失败 → 退出码 2。

#### 4.3.3 Harness 自检

- `python3 bench/runner.py --selftest` 与 `python3 bench/carriers.py --selftest`
  不启网关，跑**双工况**：
  1) 完美实现 → F1 ≈ 1.0、regression = 0
  2) 故意坏实现（丢 50% + 注入假阳性 / 跳过 tool_calls）→ 评估器**必须**报错
- 这是「评估器本身没坏」的最低保证。**任何 CI 改动前先跑 selftest。**

#### 4.3.4 第三方标注硬约束（防自证）

借鉴 privaite-bench 用 AI4Privacy / Gretel / Nemotron-PII 三方标签交叉校验的做法：

- 语料在 `bench/fixtures/cases.jsonl` 必须带 `provenance` 字段（`synthetic` / `human-annotated` / `third-party`）。
- **当前**所有 240 条均为 `synthetic`（generate.py 生成），因此报告里所有 P/R/F1 数字**不得用于对外宣称**。
- v1 发布前必须：
  - 至少新增 50 条 `human-annotated`（双盲标注 + 一致性 ≥ 0.85）
  - 至少引入 1 份 `third-party` 标注集（与 synth 取交集，差异 < 5% 才放行）
- v1.1 之后：把 `third-party` 集固化为 §16 验收「真实场景召回率」的数据源。
